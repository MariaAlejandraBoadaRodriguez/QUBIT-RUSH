# Qubit Rush — implementation decisions

Choices made autonomously where the spec leaves details open (SPEC §0, §17).
Each entry: decision, reason, how to change it.

## Engine and tooling
- **Godot 4.7.2-stable** (latest 4.x stable on 2026-10-22, verified with `git ls-remote --tags` on godotengine/godot). Pinned in `scripts/setup-env.sh` and `project.godot` (`config/features`).
- **Compatibility renderer** (`gl_compatibility`) on all platforms for OpenGL ES 3.0 devices (SPEC §3).
- **JDK 17**: the container ships JDK 21 as default; `setup-env.sh` now installs and pins JDK 17 explicitly because the Godot 4.7 Gradle template targets Java 17.
- **Android build-tools 36.1.0 / platform 36**, matching the Godot 4.7.2 Gradle template (`android/build/config.gradle`).
- **GUT 9.7.1** vendored in `addons/gut` (MIT) for headless tests. Excluded from exports.

## Quantum simulation
- Amplitudes are stored as interleaved `PackedFloat64Array` (re, im) pairs, not `Vector2`, because `Vector2` is single precision in standard Godot builds.
- **Qubit ordering:** qubit 0 is the top wire and the least significant bit of the basis index. Ket labels are written in wire order, qubit 0 first (`|q0 q1 q2⟩`). Example: `|01⟩` = q0 is 0, q1 is 1 = basis index 2. Tested in `tests/unit/test_quantum_core.gd`.
- State objectives pass at fidelity ≥ 0.999 (global-phase invariant). Distribution objectives pass at total variation distance ≤ 0.01. A state objective never passes on matching probabilities alone.
- Gate set: I, X, Y, Z, H, S, T, CNOT (measurement is modelled by Born-rule sampling on copies; Practice Lab exposes "Measure 100 times").
- v1 capped at 3 qubits (SPEC §7).

## Levels and curriculum
- Level numbering follows the §6 curriculum ranges (1–8 X/I/measurement, 9–16 H, 17–24 Z/phase, 25–32 two qubits/CNOT/Bell, 33–40 efficiency/mixed/Y/T/GHZ). The §13 onboarding beats map onto it: §13 "Level 2" (H) is level 9, "Level 3" (Z) is level 17, "Level 4" (H–Z–H) is level 20, "Level 5+" (two qubits) is level 25+.
- Added `fixed_gates` (locked, pre-placed gates) to the schema so early levels can teach X·X = I and reversibility without new gates.
- Each level stores a reference `solution`; independently, a BFS solver proves solvability and the **three-star threshold must equal the optimal gate count** (`tests/level_audit.gd`).
- Chapters: Fundamentals = 1–24, Entanglement = 25–32, Algorithms = 33–40 (the Levels tabs required by §3).
- Unlocks: linear (level n+1 unlocks after level n). Daily Challenge unlocks after level 9, Rush after level 10.

## Modes
- **Rush:** 60 seconds (within the 45–90 s range), generated 1–3 qubit challenges whose gate tier depends on progress; +1 point per solve, +2 for an optimal solve. Clock pauses on focus loss / app pause and while the consent screen is open.
- **Daily:** seed = hash of `"qubit-rush-daily-" + UTC date`. The screen shows the UTC date explicitly ("2026-10-22 UTC") to avoid timezone confusion; no global leaderboard is implied.
- **Practice Lab:** 1–3 qubits, every gate the player has met, 10 slots, live ket/probabilities/Bloch, seeded-free "Measure 100 times" on copies.

## UI
- UI is built in code from shared factories (`scripts/ui/ui.gd`, `AppTheme`) so every screen uses the same tokens. Scenes are thin `.tscn` files with the screen script.
- Base canvas 720×1440 with `canvas_items`/`expand` stretch: 1 dp ≈ 2 px. Touch targets ≥ 48 dp are enforced by `tests/ui/test_layout.gd`.
- Fonts: Inter Regular/SemiBold (OFL) plus a 5 KB DejaVu Sans subset for ⟨ ⟩ ⊗ ψ etc. (Inter lacks U+27E8/27E9).
- Kets never wrap mid-symbol: `|` is followed by U+2060 WORD JOINER in wrapped labels.
- Gates are identified by letter and colour (never colour alone); stars are shown as ★/☆ plus "n of 3 stars".
- Localisation: gettext-style keys (English source text) in `data/i18n/strings.csv`, regenerated by `tools/extract_strings.py`. Spanish: add an `es` column.

## Audio
- All sounds are synthesised at runtime (`AudioService`), so there are no third-party audio licences. Music is off by default; effects on at moderate volume. Audio stops on focus loss.

## Saves
- `user://save.json`, version 2, atomic write (tmp → verify → backup → rename), `.bak` fallback, v1→v2 migration, type repair, future versions rejected.
- In-progress circuits are saved on every edit so backgrounding or process death never loses work.

## Ads and compliance (pending owner decisions)
- **Default audience policy: `child_safe`.** Because a 10-year-old is an intended user, the app treats sessions as child-directed until the owner records a Play Console target-audience decision: child-directed + under-age-of-consent tags, max content rating G, no personalisation, **interstitials disabled**.
- Ads are **opt-in**: nothing is requested until the player chooses "Allow optional ads" (Settings > Ad choices, or from an offer) and Google UMP allows requests. Gameplay never waits on consent.
- Only a rewarded "extra hint for your next attempt" is offered, on the results screen, away from Run/Undo, never during gameplay. A basic hint is always free.
- Reward idempotency: the plugin generates one id per show; GDScript grants once per show and remembers the last 50 ids.
- Debug builds use Google's public test IDs. Release builds include the ads SDK **only** when the owner provides production IDs via environment variables at export time; otherwise the release has no ads SDK.
- AdMob SDK: `play-services-ads` 25.5.0, UMP 4.0.0 (latest stable on Google Maven on 2026-10-22), wrapped by our own small Kotlin plugin rather than a third-party Godot AdMob plugin (SPEC §2 dependency rules).

## Android packaging
- Package id `com.qubitrush.game` (changeable in `export_presets.cfg` before first Play upload; cannot change after).
- Permissions: `VIBRATE` (haptics). `INTERNET`/`ACCESS_NETWORK_STATE` come only from the ads SDK in builds that include it.
- Debug APK includes arm64-v8a, armeabi-v7a and x86_64 (for emulators). Release AAB: arm64-v8a + armeabi-v7a.
- minSdk 26 (Android 8.0) and targetSdk 36 via the Gradle build.
